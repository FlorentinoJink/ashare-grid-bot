# 格间 · A 股网格交易 Bot

Rust 编写的本地网格信号工作台。在浏览器选择股票、预览等差或等比网格、启动策略，触价后通过飞书应用把限价和股数发给接收人。实际委托由用户在券商端完成，工作台按人工登记的成交回报更新账本。

## 启动

需要 Rust 1.91 或更新版本以及本机 C 编译工具链。Windows 可用 Visual Studio 的「使用 C++ 的桌面开发」组件。网页资源随二进制编译，无需安装 Node.js。

```sh
git clone https://github.com/FlorentinoJink/ashare-grid-bot.git
cd ashare-grid-bot
cargo run --release --locked
```

打开 [本地控制台](http://127.0.0.1:8716)。服务进程持续运行时才会轮询行情。首次启动没有策略，页面预填的区间和资金仅供编辑。

### 接入已有飞书应用

应用需开启机器人能力、发布给目标用户，并具备 `im:message:send_as_bot` 等发送权限。接收人的 Open ID 必须属于同一应用。配置完成后，可在页面点「测试飞书连接」，向该接收人发送一条测试私信。[飞书发送消息 API](https://open.feishu.cn/document/server-docs/im-v1/message/create)

可以从环境变量读取 `TRADER_FEISHU_APP_ID`、`TRADER_FEISHU_APP_SECRET`、`TRADER_FEISHU_OPEN_ID`，也可以用 `FEISHU_CONFIG_FILE` 指向仓库外的历史 TOML 配置。环境变量优先，本机配置示例结构如下。

```toml
[feishu]
AppID = "<应用 ID>"
AppSecret = "<应用密钥>"
OpenID = "<接收人的 Open ID>"
```

PowerShell 启动示例

```powershell
$env:FEISHU_CONFIG_FILE = 'C:\private\feishu\config.toml'
cargo run --release --locked
```

凭据仅在服务端使用。省略飞书配置即可使用本地信号和成交登记。服务绑定 IPv4 回环地址，可通过 `GRID_PORT` 修改端口，`GRID_DB` 指定 SQLite 文件，默认使用当前目录下的 `data/grid.sqlite`。

## 策略分页

- [网格交易](http://127.0.0.1:8716/) 配置和运行网格，跟踪触价、通知和成交。
- [红利收息](http://127.0.0.1:8716/dividends) 按证券代码及年度保存手工录入的分红基准、公告进度、参考价和持仓。页面计算参考股息率、对应目标股息率的价格以及年度税前分红。
- [股债配置](http://127.0.0.1:8716/allocation) 按组合名称保存红利权益及债券市值和目标权重，以总市值不变计算偏离与调整额。

红利和配置页面使用手工数据，保存后写入本机 SQLite，支持重新打开编辑。这两页用于测算，飞书触价推送由网格策略运行。

## 网格如何运行

1. 输入六位股票代码，填写上下限、格数、每格股数、分配给该策略的现金和已有可卖底仓。页面根据最近报价预填约 ±5% 的区间，启动前可覆盖。不同策略分别记账，同一笔现金或持仓应只分配一次。
2. **N 格产生 N+1 个价位。** 等差模式的间距为 `(上限 − 下限) / N`，等比模式的倍率为 `(上限 / 下限)^(1/N)`。网格价四舍五入到分，碰到重复价位会提示减少格数。区间和模式参考[币安现货网格说明](https://www.binance.com/en/support/faq/detail/d5f441e8ab544a5b98241e00efb3a4ab)。
3. 首个有效盘中报价作为基准。对下边界位于基准及以上的区间，从近到远按可卖底仓分配待卖格，其余区间等待买入。下穿待买格的下沿产生买入信号，上穿待卖格的上沿产生卖出信号。触达即计作穿越，同一时间戳或重复报价不会重复触发。
4. 跳空跨多档时按穿越方向逐档检查。待处理信号占用对应资金或可卖股数。余额不足的档位跳过，下一次重新穿越时再检查。行情超出上下限后，只有区间内的边界能够触发。
5. 勾选「触发时推送飞书」会将股票、方向、股数、信号限价、参考金额、行情时间、信号编号发到飞书。网页保留每笔订单的投递状态。
6. 按券商回报登记**信号当日整笔成交**的实际价格和总费用。买入允许更低的实际成交价，卖出允许更高的实际成交价。成交后该格转向另一侧边界。买入股数当天锁定，下一交易日可用于卖出；原有可卖底仓可继续使用。仅取消未成交信号会释放对应预留。当前版本只支持整笔成交登记。
7. 暂停会停止生成新订单。已有待处理订单继续保留，恢复后用首个有效报价重新建立穿越基准。过夜未处理的信号保留至人工核对当日成交或取消，避免提前释放资金。订单列表显示全部待处理记录和最近 100 笔已处理记录。

## 行情与板块

内置腾讯行情快照适配器。工作日北京时间 09:30–11:30、13:00–14:57 轮询，结束时刻不含在内。每轮按股票合并请求，完成后等待 8 秒。仅接受连续竞价时段内、距本机时间不超过 90 秒的报价，午休、周末、未来时间戳及旧报价均不触发。没有独立节假日日历，节假日的工作日时段仍可能发起查询。报价接口为公开快照服务，时效性和字段格式取决于供应方；轮询间隔内触及后回撤的价格可能被漏过。

## 实现与验证

- `grid.rs` 管理以分为单位的价位、区间方向、资金预留和 T+1 数量。
- `market.rs` 解析带原始时间戳的快照，`workers.rs` 负责行情轮询和通知投递。
- `store.rs` 使用 SQLite 事务同步保存网格状态、预留和信号。成交登记具有单次生效语义。将同一数据库用于一个运行实例。
- `feishu.rs` 缓存租户令牌，每笔信号复用同一个飞书消息 UUID。发送失败后退避重试，最多 5 次；超过行情时间 3 分钟或离开连续竞价时段后停止补发。投递失败、过期、已发送均在页面区分。订单执行情况仍以用户登记为准。
- `main.rs` 提供本机 HTTP API，`web/` 是嵌入程序的中文页面。

```sh
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

测试包含价位取整、板块数量约束、跨档资金预留、T+1、过期报价、SQLite 重启恢复、并发重复登记及飞书模拟服务的失败重试。
